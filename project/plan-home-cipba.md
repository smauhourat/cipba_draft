- [x] **Conversión a bloques nativos — solo "Contacto por función".** A pedido del usuario, se pasó esta sección (únicamente esta, las demás siguen en HTML crudo) de un bloque "HTML personalizado" a bloques nativos editables: Group (`.cipba-section` → `.cipba-wrap` → `.cipba-section-head`/`.cipba-contact-grid`) con Heading/Paragraph reales para título, textos y links de mail de cada tarjeta — ahora se editan desde el editor visual sin tocar HTML. La fila de íconos sociales se dejó como bloque HTML anidado (mismo SVG de siempre): no es contenido que se edite seguido y el editor (RichText) no preserva SVG crudo dentro de un párrafo de forma confiable, así que no convenía forzarlo. El ícono de sobre en los links de mail se pasó de SVG inline a CSS (`::before` con `mask`), para que el link quede como texto plano editable. **Riesgo conocido (mismo de las FAQ): `theme.json` le pone 52px de padding top/bottom a todo `core/group` por defecto.** Se resolvió reforzando con `!important` el padding real de `.cipba-section`, `.cipba-wrap`, `.cipba-section-head`, `.cipba-contact-grid` y `.cipba-contact-card` en `style.css`, en vez de pelear con los atributos de estilo del bloque (que WordPress a veces aplica vía una clase generada + hoja de estilos separada, no inline, y es más frágil de verificar por script). Verificado: `parse_blocks()` arma el árbol de bloques esperado (Group > Group > Group/Heading + Group > [Group > Heading+Paragraph+Paragraph] × 2, HTML), sin bloques inválidos, y el render vía `the_content` no tira fatales y contiene todos los textos/clases esperados. **Fix posterior:** el usuario reportó "este bloque ha encontrado un error y no puede previsualizarse" en las 2 tarjetas al abrir el editor. Consola: `TypeError: Cannot read properties of undefined (reading 'getOrientation')`. Causa: los 4 Group internos (section-head, contact-grid, las 2 contact-card) se guardaron con `"layout":{"type":"flow"}` — ese nombre de tipo no existe en la versión actual de Gutenberg (`getLayoutType('flow')` devuelve `undefined`, y el editor revienta al llamar `.getOrientation` sobre eso). El tipo correcto para un layout de flujo plano es `"default"`. Corregido con un `str_replace` puntual de `"layout":{"type":"flow"}` → `"layout":{"type":"default"}` en las 4 ocurrencias del post_content de la página 81. Verificado sin fatales y con el contenido esperado presente. **Falta confirmación visual del usuario** (frontend y editor, ahora sin el error) — ver Progreso.
